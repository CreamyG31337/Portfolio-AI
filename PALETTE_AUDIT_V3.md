# 🎨 Palette Audit Report V3

This document outlines new findings from a design system and CSS audit of the `web_dashboard` codebase. It focuses on identifying specific instances of custom CSS, direct DOM manipulation, and inconsistent component usage that can be replaced with standard Tailwind utilities and Flowbite components.

## 🚨 Critical Findings

### 1. Duplicate CSS in Templates
**Location:** `web_dashboard/templates/users.html`
**Issue:** A `<style>` block defines custom classes that duplicate existing Tailwind utilities and Flowbite patterns.
```css
.user-card { transition: transform 0.2s ease-in-out; border: 1px solid var(--border-color); }
.user-card:hover { transform: translateY(-2px); box-shadow: 0 4px 6px rgba(0, 0, 0, 0.1); }
.role-badge { ... }
.popover-content { ... }
```
**Why it matters:** This creates "shadow styling" that isn't controlled by the central Tailwind config. It reinvents Cards, Badges, and Popovers which are already standard Flowbite components.
**Suggestion:**
*   Replace `.user-card` with: `border border-border transition-transform duration-200 hover:-translate-y-0.5 hover:shadow-lg`.
*   Replace `.role-badge` with Flowbite Badge classes: `inline-flex items-center px-2.5 py-0.5 rounded font-medium text-xs`.
*   Replace `.popover-content` with Flowbite Popover data attributes.
**Scope:** Local (File-level)

### 2. Direct JS Style Manipulation
**Location:** `web_dashboard/src/js/dashboard.ts` (specifically `TickerCellRenderer` class)
**Issue:** The code directly assigns styles to DOM elements via the `.style` property.
```typescript
this.eGui.style.display = 'flex';
this.eGui.style.alignItems = 'center';
tickerSpan.style.color = 'var(--color-accent)';
```
**Why it matters:** This bypasses Tailwind's utility classes and hardcodes style values in JavaScript, making it harder to theme or update globally. It also misses the opportunity to use responsive prefixes if needed later.
**Suggestion:** Use `.className` assignment with Tailwind utilities:
```typescript
this.eGui.className = 'flex items-center gap-1.5';
tickerSpan.className = 'text-accent font-bold underline cursor-pointer';
```
**Scope:** Local (Component-level)

### 3. Hardcoded Colors in JS Logic
**Location:** `web_dashboard/src/js/dashboard.ts` (Action Queue rendering)
**Issue:** Hardcoded Tailwind color shades are mapped in the `actionColors` object.
```typescript
'BUY': 'bg-green-100 text-green-800 ...',
'SELL': 'bg-red-100 text-red-800 ...'
```
**Why it matters:** The `tailwind.config.js` defines semantic status colors (`theme-success`, `theme-error`). Using `green-100` directly couples the logic to specific shades rather than the design system's intent.
**Suggestion:** Switch to semantic tokens:
*   `BUY` -> `bg-theme-success-bg text-theme-success-text`
*   `SELL` -> `bg-theme-error-bg text-theme-error-text`
**Scope:** Systemic (Design Token Usage)

### 4. Manual Pagination Implementation
**Location:** `web_dashboard/templates/logs.html`
**Issue:** Pagination controls are manually implemented using custom buttons (`btn-pagination`) and JavaScript logic.
**Why it matters:** Flowbite offers a standardized [Pagination component](https://flowbite.com/docs/components/pagination/) that handles state, icons, and accessibility (ARIA labels) consistently. The manual implementation duplicates this effort.
**Suggestion:** Replace custom buttons with the Flowbite Pagination structure.
**Scope:** Local

### 5. Inconsistent Tabs Implementation
**Location:** `web_dashboard/templates/dashboard.html` vs `web_dashboard/templates/users.html` vs `web_dashboard/templates/jobs.html`
**Issue:**
*   `jobs.html`: **Good.** Uses Flowbite's `data-tabs-toggle` API.
*   `dashboard.html`: **Custom.** Uses manual `onclick` handlers and custom class toggling for time ranges.
*   `users.html`: **Custom.** Uses custom `.tab-button` classes and manual JS logic.
**Why it matters:** Inconsistent UX and code maintainability. Users navigating with keyboards might find different behaviors on different pages.
**Suggestion:** Standardize all tab-like interfaces (including time range selectors) to use Flowbite's `data-tabs-toggle` or Button Group components for consistency.
**Scope:** Systemic

## 🎨 Best Practice Violations

### 6. Legacy FontAwesome Usage
**Location:** Global
**Issue:** Continued use of `fas fa-*` icons instead of SVG icons.
**Why it matters:** SVG icons (like Heroicons, used by standard Flowbite) are lighter and easier to style with Tailwind (`w-5 h-5 text-gray-500`).
**Suggestion:** Prioritize converting icons in new or refactored components to inline SVGs.
