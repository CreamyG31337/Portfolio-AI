# 🎨 Palette Audit Report V3

This document outlines new findings from a design system and CSS audit of the `web_dashboard` codebase, building upon the previous audits. The goal is to identify opportunities to better leverage Tailwind CSS and Flowbite, improve accessibility, and ensure maintainability.

## 🚨 Critical Findings

### 1. Inline Styles for Composite Bars
**Location:** `web_dashboard/templates/ticker_details.html`, `web_dashboard/src/js/ticker_details.ts`
**Issue:** The width of the momentum and fund composite bars are managed via inline `style="width: X%"` updates in JS instead of Tailwind utilities.
**Why it matters:** Inline styles violate the utility-first philosophy, bypass the Tailwind build process, and make debugging state harder.
**Suggestion:** Use CSS variables (e.g., `style.setProperty('--bar-width', ...)` in JS) and Tailwind's arbitrary value syntax for width (`w-[var(--bar-width,0%)]`) to manage the visual width, removing the direct `style.width` manipulation.
**Scope:** Local (Component-level)

### 2. Custom Drawer Backdrop
**Location:** `web_dashboard/templates/ai_assistant.html`
**Issue:** A drawer backdrop is manually implemented using `hidden fixed inset-0 bg-black/50 z-40`.
**Why it matters:** Flowbite provides a standardized [Drawer component](https://flowbite.com/docs/components/drawer/) that handles focus trapping, backdrop click-to-close behavior, and ARIA attributes out of the box. Custom implementations often lack these accessibility features.
**Suggestion:** Replace the custom drawer and backdrop state handling with Flowbite's Drawer API (`data-drawer-target`, `data-drawer-show`, `data-drawer-hide`).
**Scope:** Local

### 3. Custom Modal Implementation
**Location:** `web_dashboard/templates/trade_entry.html`, `web_dashboard/templates/newsletters.html`
**Issue:** Modals are implemented manually (`hidden fixed top-0 right-0 left-0 z-50...`) and use custom JS to toggle visibility.
**Why it matters:** Custom modals often miss crucial accessibility features like focus trapping and `Esc` key support, which Flowbite's Modal API handles automatically.
**Suggestion:** Migrate edit/delete trade dialogs and email view modals from custom markup/JS to Flowbite Modal components.
**Scope:** Reusable

### 4. Hardcoded AG Grid Row Highlight Colors
**Location:** `web_dashboard/templates/insider_trades.html`
**Issue:** Hardcoded RGBA values (`rgba(0, 200, 83, 0.08)`, `rgba(255, 82, 82, 0.08)`) are used in an inline `<style>` block to highlight grid rows.
**Why it matters:** Hardcoded colors break theme consistency, especially in dark mode, and bypass the design token system established in the Tailwind config and `theme.css`.
**Suggestion:** Replace the inline `<style>` with Tailwind classes in `input.css` using `theme()` or CSS variables mapped to the project's theme tokens (e.g., `--color-success-bg`).
**Scope:** Local

### 5. Custom Time Range Selector
**Location:** `web_dashboard/templates/dashboard.html`
**Issue:** The time range selector ("1M", "3M", "All") uses a custom group markup and `aria-pressed` logic.
**Why it matters:** Flowbite offers a canonical Button Group pattern. Reinventing this pattern can lead to inconsistent border collapsing and focus states.
**Suggestion:** Recheck and swap the custom group markup to a standard Flowbite button-group pattern, utilizing Flowbite's JS API for state management if applicable.
**Scope:** Local
