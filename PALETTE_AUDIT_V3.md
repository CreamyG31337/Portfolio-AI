# 🎨 Palette Audit Report V3

This document outlines new findings from a design system and CSS audit of the `web_dashboard` codebase, building upon previous audits. The goal is to identify opportunities to better leverage Tailwind CSS and Flowbite, improve accessibility, and ensure maintainability.

## 🚨 Critical Findings

### 1. Manual Drawer Implementation for Mobile
**Location:** `web_dashboard/templates/ai_assistant.html`
**Issue:** The mobile AI drawer and its backdrop are implemented manually using custom toggles and inline classes (`hidden fixed inset-0 bg-black/50 z-40 transition-opacity duration-300 md:hidden` and associated JS logic in `dashboard.ts`).
**Why it matters:** Manually implementing drawers often misses critical accessibility features like focus trapping and ARIA roles. Flowbite offers a robust Drawer component.
**Suggestion:** Replace the custom implementation with [Flowbite's Drawer component](https://flowbite.com/docs/components/drawer/). Use `data-drawer-target` and related attributes for consistent behavior.
**Scope:** Local (Component-level)

### 2. Manual Modal Implementations
**Location:** `web_dashboard/templates/trade_entry.html`, `web_dashboard/templates/newsletters.html`
**Issue:** The Edit/Delete trade dialogs and the Email View modal are implemented using custom markup and vanilla JS to toggle visibility (e.g., removing `hidden` classes).
**Why it matters:** Flowbite provides a standardized [Modal component](https://flowbite.com/docs/components/modal/) API (`data-modal-target`, `data-modal-hide`) that manages accessibility, keyboard navigation (Escape to close), and body scroll locking automatically. Custom logic duplicates this effort and risks edge-case bugs.
**Suggestion:** Migrate these dialogs to use the Flowbite Modal API to reduce JS boilerplate and improve accessibility.
**Scope:** Reusable (System-wide pattern)

## 🎨 Best Practice Violations

### 3. Inline Styles for Progress Bars
**Location:** `web_dashboard/templates/ticker_details.html`, `web_dashboard/src/js/ticker_details.ts`
**Issue:** Composite score progress bars dynamically inject width via inline styles: `style="width: X%"`.
**Why it matters:** While dynamic, inline styles bypass the utility class system and CSS variables constraint approach. The codebase has established a pattern of mapping these to utility combinations.
**Suggestion:** Use inline CSS variables (`style="--bar-width: X%"`) and Tailwind's arbitrary value syntax for width (`w-[var(--bar-width)]`) to keep layout instructions fully within the class definition structure.
**Scope:** Local

### 4. Hardcoded Table Row Highlight Colors
**Location:** `web_dashboard/templates/insider_trades.html`
**Issue:** AG Grid row highlights use hardcoded RGBA values in a custom `<style>` block:
```css
.ag-row.insider-trade-purchase .ag-cell { background-color: rgba(0, 200, 83, 0.08); }
.ag-row.insider-trade-sale .ag-cell { background-color: rgba(255, 82, 82, 0.08); }
```
**Why it matters:** This circumvents the Tailwind theme token system defined in `tailwind.config.js` and CSS variables, meaning these colors won't automatically respond to theme changes (e.g., dark mode adjustments) and create visual inconsistencies.
**Suggestion:** Extract these styles to `input.css` using the `@apply` directive with Tailwind's theme color utilities (e.g., `bg-theme-success-bg` / `bg-theme-error-bg` with opacity modifiers).
**Scope:** Local

## ✅ Proposed Action Plan

1.  **Migrate Drawers/Modals:** Systematically replace manual JS toggles with Flowbite `data-modal-target` and `data-drawer-target` attributes across the listed templates.
2.  **Refactor Progress Bars:** Update `ticker_details.ts` to set CSS variables instead of inline width styles.
3.  **Tokenize AG Grid Highlights:** Move the inline `<style>` from `insider_trades.html` into `input.css` and use theme tokens.
