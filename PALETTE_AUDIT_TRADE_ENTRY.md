# 🎨 Palette Audit Report: Trade Entry Modals

This report identifies opportunities to better leverage Flowbite components within the Trade Entry page (`web_dashboard/templates/trade_entry.html` and `web_dashboard/src/js/trade_entry.ts`) to improve accessibility, maintainability, and code consistency.

## 🚨 Findings

### 1. Manual "Edit Trade" Modal Implementation
**Issue:** The "Edit Trade" dialog is implemented using custom markup (`<div id="edit-trade-modal" class="hidden fixed inset-0 z-50 flex items-center justify-center bg-black/50">`) and managed by manual JavaScript event listeners (e.g., `classList.remove('hidden')`, manual backdrop click handlers, and a global Escape key listener).
**Why it matters:**
- **Accessibility:** The custom implementation lacks proper focus trapping, ARIA roles, and `aria-hidden` management, which are critical for screen readers and keyboard navigation.
- **Maintainability:** Re-implementing modal logic (including backdrop and keyboard event handling) duplicates code that Flowbite already provides out-of-the-box.
- **Consistency:** Other parts of the dashboard use standard Flowbite modal components (e.g., in `funds.html`). Mixing custom modals with framework components creates an inconsistent developer experience.
**Suggestion:**
- Replace the custom HTML wrapper with the standard Flowbite modal structure (e.g., using classes like `overflow-y-auto overflow-x-hidden fixed top-0 right-0 left-0 z-50 justify-center items-center w-full md:inset-0 h-[calc(100%-1rem)] max-h-full`).
- Add a hidden trigger button with `data-modal-target="edit-trade-modal"` and `data-modal-toggle="edit-trade-modal"`.
- Update the close and cancel buttons to use `data-modal-hide="edit-trade-modal"`.
- Refactor `trade_entry.ts` to trigger the modal via the Flowbite API or by simulating a click on the hidden trigger, and remove the custom event listeners for the backdrop and Escape key.
**Scope:** Reusable Component (Modal)

### 2. Manual "Delete Trade" Modal Implementation
**Issue:** Similar to the Edit modal, the "Delete Trade" confirmation dialog uses custom HTML classes (`<div id="delete-trade-modal" class="hidden fixed inset-0 z-50 flex items-center justify-center bg-black/50">`) and relies on custom JavaScript logic for visibility toggling and event handling.
**Why it matters:** This duplicates the same accessibility and maintainability issues as the Edit modal. It bypasses Flowbite's built-in keyboard navigation and focus management.
**Suggestion:**
- Refactor the markup to follow Flowbite's standard modal component.
- Utilize `data-modal-target` and `data-modal-hide` attributes.
- Remove redundant JavaScript logic in `trade_entry.ts` responsible for closing the modal on backdrop clicks or Escape key presses.
**Scope:** Reusable Component (Modal)
